## Project Overview

This is the user documentation site for the Open Science Portal (OSP), maintained by the Open Science Branch of Fisheries and Oceans Canada. It's a bilingual (English/French) static documentation site built with Docusaurus 3 (React, TypeScript, MDX).

**Live site:** https://osp-pso-docs.ent.dfo-mpo.ca/

## Development Commands

### Setup
```bash
pnpm install
```

The `.env` file (see `.env.example`) must define `TYPESENSE_SEARCH_API_KEY` and `TYPESENSE_PUBLIC_HOST`. `docusaurus.config.ts` throws at startup if either is missing. `TYPESENSE_PORT` and `TYPESENSE_PROTOCOL` are optional and default to `8108` and `http`.

### Development server
```bash
pnpm start
# Runs on http://localhost:3000 (English only; use `pnpm build && pnpm serve` to test the French locale)
```

### Build
```bash
pnpm maps:build   # regenerates the DFO region SVG map data; run before build if the geojson changes
pnpm build        # outputs to build/
pnpm serve        # serves the built site locally
```

### Other
```bash
pnpm typecheck    # tsc
pnpm lint         # eslint
pnpm lint:fix
pnpm write-translations -- --locale fr
```

## Project Architecture

### Bilingual Structure
English is the default locale; French is configured under `i18n` in `docusaurus.config.ts`.

- **English content:** `docs/`
- **French content:** `i18n/fr/docusaurus-plugin-content-docs/current/` (mirrors the `docs/` structure)
- **UI strings / sidebar labels:** `i18n/{en,fr}/code.json`, `i18n/{en,fr}/docusaurus-theme-classic/`, and `i18n/fr/docusaurus-plugin-content-docs/current.json`

Top-level doc sections: `portal-basics/`, `common-features/`, `manuscript-record-forms/`, `manuscript-management-review/`, `publications/`, `settings/`, `references/`, plus `index.mdx` and `frequently-asked-questions.mdx`.

### Docusaurus Configuration
- **Main config:** `docusaurus.config.ts` (navbar, footer, i18n, Typesense search, Mermaid)
- **Sidebar:** `sidebars.ts` — autogenerated from the `docs/` folder structure, so ordering and labels come from folder/file names, `_category_.json` and front matter.
- `onBrokenLinks` is `'throw'`, so broken internal links fail the build.
- **Search:** `docusaurus-theme-search-typesense`, collection `osp_pso_docs`.

### Custom code
- `src/components/` — React components used in MDX (e.g. `SupportEmail`, `ExternalLocalizedLink`, `DfoRegionsMap`, `TurnaroundMap`, `OnboardingWidget`)
- `src/data/` — shared contact info and external links
- `src/theme/` — swizzled theme components (`EditThisPage`, `Footer`)
- `src/css/custom.css` — site styles
- `scripts/geojson-to-dfo-svg.mjs` — builds map data from `scripts/data/dfo-regions.geojson`

### Static assets
`static/` (and `src/`, both listed in `staticDirectories`):
- `static/img/` — logos, favicon, social card, documentation images
- `static/maps/`, `static/data/` — generated map and data files

### Content Organization

When editing documentation:
1. **Bilingual changes:** Update both `docs/` and `i18n/fr/docusaurus-plugin-content-docs/current/` in parallel.
2. **Task pages** follow the progressive disclosure model described in `CONTRIBUTION.md` (steps first, supporting information separate).
3. **Images:** Place in `static/img/` and reference with an absolute path such as `/img/filename.png`.
4. Use `.mdx` extensions in internal links.

## Deployment

`.github/workflows/deploy.yml` (push to `main` or manual dispatch) runs on a self-hosted runner and uses the `production` environment:

1. `build-docs` builds the site and packs `build/` into `osp-docs_<sha>.tar.gz` as `public/`.
2. `deploy` uploads the tarball over SSH to `<app_root>/artifacts` and runs `activate-docs-release.py <sha>` on the server.

The server side (nginx, the Typesense container and scraper, the activation script and its `deployDocs.ini`) is managed in the separate **osp-ansible** repo (`roles/osp_docs_cd`). Keep the artifact layout and the secrets/variables used by the workflow in sync with that role.

Workflow secrets: `SERVER`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `TYPESENSE_SEARCH_API_KEY`. Variables: `TYPESENSE_PORT` (default `443`), `TYPESENSE_PROTOCOL` (default `https`).
